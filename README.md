# Sakk (صك)

A Flutter app for tracking purchases, warranties, returns and receipts. Available in English and Arabic, on Android and iOS.

## Features

- **Products** — record purchases with their warranty and return window. Each product can hold documents (receipt, warranty card, photos, manual), extra warranties from other providers, and warranty claims tracked from submitted to resolved or rejected. The app warns before you save a likely duplicate (same invoice number, serial number, or name and date). Search by name, brand, store, serial or invoice number, and share all products as a CSV file.
- **Receipt scanning** — take a photo, pick an image, or choose a PDF of a receipt, invoice or warranty card (Arabic, English or both). AI fills in the product, brand, store, price, purchase date, warranty length, serial and invoice numbers and category for you to review before saving. Prices are in EGP; receipts in another currency show the original amount.
- **AI chat** — an assistant that knows your products and their warranty dates. It helps with using the app, warranty rights, what to do when something breaks, and buying advice, and declines unrelated topics.
- **Subscriptions** — online services you pay for (Netflix, Shahid...) with price, billing cycle and next renewal date, added from a list of known services, a screenshot or bank SMS, or by hand; reminders before each renewal and the total per month.
- **Installments** — purchases paid off monthly (bank, Valu, Contact, Sympl, the store...), optionally linked to a product, with each payment's due date, reminders before it's due and a "Mark as paid" button on the notification.
- **My papers** — official papers (national ID, passport, driving and car licences, car and medical insurance, rental contract...) with a photo of each side, the number and the expiry date; reminders a month before, a week before and on the day. Private to the user: not shared with the household and never sent to the AI.
- **Sakk Pro** — a paid plan (monthly or yearly, 7-day free trial) that removes the free plan's limits and adds the monthly summary with a PDF report, earlier reminders and Add by voice (say what you bought, in Arabic or English, and the form fills itself). See [Sakk Pro](#sakk-pro-free-plan-limits).
- **Households** — create a household or join one with a 10-character invite code; members see each other's products. The owner can remove members and generate a new code.
- **Reminders** — local notifications before a warranty ends (90, 30, 7 or 1 days ahead, your choice) and 2 days before a return window closes, plus an in-app notifications list. You can also add the warranty end or return deadline to your calendar.
- **Home screen widget** — shows the next warranty to end and its end date, on Android and iOS.
- **Analytics** — total spent (can be hidden), spending by year, top 5 stores, a category breakdown donut chart, and how many warranties are active, expiring or expired; switch between your own products and the household's.
- **Account** — sign in with email and password or Google, reset a forgotten password with an emailed code, and delete your account. An optional biometric lock asks for your fingerprint or face when the app opens.

## Tech stack

| Area | Library |
|---|---|
| State | `flutter_bloc` (Cubits only) |

| Localization | `flutter_localizations` + ARB files in `lib/l10n` (English, Arabic) |

Features use clean architecture layers, but only the ones they need:

| Feature | Layers |

## Getting started

### Requirements

- Flutter 3.41 (stable) or newer — the project needs Dart `^3.11.5`
- **Android:** Android Studio and the Android SDK. Gradle needs Java 17 or 21; Gradle 8.14 does not run on Java 25. If that is your default, use Android Studio's bundled JDK:
  ```
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```
- **iOS:** Xcode and CocoaPods. The Podfile targets iOS 15.0.

### Environment

Create a `.env` file in the project root. It is git-ignored, but it is listed as an asset in `pubspec.yaml`, so **the app will not build without it**. It is bundled into the app, so anyone can read it from the APK: put only public keys here, never a secret (service role key, Groq key, webhook secret):

```
SUPABASE_URL=
SUPABASE_ANON_KEY=
GOOGLE_WEB_CLIENT_ID=
GOOGLE_IOS_CLIENT_ID=
REVENUECAT_ANDROID_KEY=
```

`REVENUECAT_ANDROID_KEY` is RevenueCat's public Android SDK key (`goog_...`), not a secret. Without it the app runs on the free plan and the paywall says subscriptions aren't available.

The Firebase config (`lib/firebase_options.dart`, `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist`) is committed, so Crashlytics works without extra setup.

If you use a different `GOOGLE_IOS_CLIENT_ID`, also update the reversed client ID in `CFBundleURLSchemes` in `ios/Runner/Info.plist`.

### Run

```
flutter pub get
flutter run
```

On iOS, `flutter run` installs the pods automatically. Translations are generated from `lib/l10n/*.arb` on build; after editing an ARB file, run `flutter gen-l10n` to update them without a full build.

### Test and lint

```
flutter test
flutter analyze
dart format lib test
```

CI (`.github/workflows/checks.yml`) fails if any file isn't formatted.

### iOS home screen widget

The widget's Swift code is in `ios/SakkWarrantyWidget`, but its Xcode target and the `group.com.sakk.app` App Group have to be set up once in Xcode. Follow [`ios/SakkWarrantyWidget/README.md`](ios/SakkWarrantyWidget/README.md). The Android widget needs no setup.

### Regenerating icons and splash

After changing the artwork in `assets/`:

```
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

## Google sign-in

The app signs in with Google's ID token and passes it to Supabase.

- `GOOGLE_WEB_CLIENT_ID` is the **Web** OAuth client. It is used as `serverClientId` on both platforms and must be added to Supabase's Google provider.
- `GOOGLE_IOS_CLIENT_ID` is the iOS OAuth client for bundle ID `com.sakk.app`.
- **Android** needs an Android OAuth client for package `com.sakk.app` in the same Google Cloud project — one per signing key (debug, upload, and Play App Signing). Without it, choosing an account does nothing: Credential Manager reports the error as a cancellation, which the app logs as `Google sign-in cancelled`.

To print the debug and upload key SHA-1s:

```
cd android && ./gradlew signingReport
```

The Play App Signing SHA-1 is in Play Console → Setup → App integrity.

## Release builds (Android)

Build the Play bundle obfuscated, with the Dart symbols kept apart:

```
flutter build appbundle --release --obfuscate --split-debug-info=build/symbols
```

`build/symbols` is git-ignored, and `flutter clean` deletes it: copy it somewhere safe for every version you upload (e.g. `symbols/1.0.0+2/`). Without that version's symbols, its obfuscated crash reports can't be read (`flutter symbolize`). R8 keep rules are in `android/app/proguard-rules.pro`.

To send a test build outside Play, build per-ABI APKs and send `app-arm64-v8a-release.apk` (nearly all current phones):

```
flutter build apk --release --split-per-abi --obfuscate --split-debug-info=build/symbols
```

Release signing reads `android/key.properties` (git-ignored):

```
storePassword=
keyPassword=
keyAlias=upload
storeFile=/path/to/sakk-upload.jks
```

Without it, release builds fall back to the debug key.

## Supabase

Apply the schema from `supabase/migrations` and deploy the edge functions with the Supabase CLI. On a new project `supabase db push` builds everything, starting from `20261001000000_base_schema.sql` (the products and notifications tables and storage buckets that were first made in the dashboard). The live project already had those, so that one migration is marked as applied there rather than run (`supabase migration repair --status applied 20261001000000`).


```
supabase db push
supabase functions deploy ai-chat
supabase functions deploy extract-receipt
supabase functions deploy delete-account
supabase functions deploy revenuecat-webhook --no-verify-jwt
```

The AI functions need a `GROQ_API_KEY` secret:

```
supabase secrets set GROQ_API_KEY=...
```

The RevenueCat webhook needs the Authorization value you set in RevenueCat, and optionally a secret REST API key (`sk_...`) so each event re-reads the subscriber from RevenueCat:

```
supabase secrets set REVENUECAT_WEBHOOK_SECRET=... REVENUECAT_API_KEY=...
```

## Sakk Pro (free plan limits)

- Limits live in the `app_config` table (key `limits`), read by the database and shown by the app. They start unlimited; switch on the launch values (in the comment in `20261018120000_pro_plan.sql`) once the release with the paywall is out. Change them in the SQL editor, no release needed; `null` means unlimited:
  ```sql
  update app_config set value = jsonb_set(value, '{free,scan_per_day}', '5') where key = 'limits';
  ```
- Enforced on the server: `BEFORE INSERT` triggers on `products`, `user_subscriptions`, `installment_plans` and `papers` raise `LIMIT_REACHED:<item>`, and the AI functions (`extract-receipt`, `ai-chat`) take one from `consume_quota` before calling Groq and answer 402 when none are left. Days start at midnight Cairo time.
- Pro is `pro_subscriptions.active_until > now()`, kept up to date by `revenuecat-webhook`. When Pro ends nothing is deleted or hidden; only new items above the free limits are refused.
- The app logs in to RevenueCat with the Supabase user id, so RevenueCat's `app_user_id` is the user's id.
- Add by voice: the app records up to a minute (16 kHz AAC), uploads it to the user's receipts folder, and `extract-receipt` (mode `voice`) transcribes it with Groq's `whisper-large-v3`, reads the product fields from the words, and the app deletes the recording. It takes a `voice` from the daily quota: `voice_per_day` is 0 on the free plan (Pro only) and a fair-use 30 on Pro.
- Papers: the free plan keeps 2 (`papers` in `limits`), Pro has no limit. Photos are in their own private `papers` bucket, readable only by their owner (unlike `receipts`, which household members can read for shared products), and signed for an hour when the list loads. Paper reminders use negative notification ids, so they never share a slot with the others.
- Pro-only in the app: Add by voice, the monthly summary (with a PDF report) and an earlier reminder for subscriptions and installments (5, 7, 10 or 14 days ahead, on the Reminders screen; notification slot 9, shared and told apart by payload). Free users keep every reminder they had.
