# Sakk (صك)

A Flutter app for tracking purchases, warranties, returns and receipts. Available in English and Arabic, on Android and iOS.

## Features

- **Products** — record purchases with their warranty and return window. Each product can hold documents (receipt, warranty card, photos, manual), extra warranties from other providers, and warranty claims tracked from submitted to resolved or rejected. The app warns before you save a likely duplicate (same invoice number, serial number, or name and date). Search by name, brand, store, serial or invoice number, and share all products as a CSV file.
- **Receipt scanning** — take a photo, pick an image, or choose a PDF of a receipt, invoice or warranty card (Arabic, English or both). AI fills in the product, brand, store, price, purchase date, warranty length, serial and invoice numbers and category for you to review before saving. Prices are in EGP; receipts in another currency show the original amount.
- **AI chat** — an assistant that knows your products and their warranty dates. It helps with using the app, warranty rights, what to do when something breaks, and buying advice, and declines unrelated topics.
- **Households** — create a household or join one with a 10-character invite code; members see each other's products. The owner can remove members and generate a new code.
- **Reminders** — local notifications before a warranty ends (90, 30, 7 or 1 days ahead, your choice) and 2 days before a return window closes, plus an in-app notifications list. You can also add the warranty end or return deadline to your calendar.
- **Home screen widget** — shows the next warranty to end and its end date, on Android and iOS.
- **Analytics** — total spent (can be hidden), spending by year, top 5 stores, a category breakdown donut chart, and how many warranties are active, expiring or expired; switch between your own products and the household's.
- **Account** — sign in with email and password or Google, reset a forgotten password with an emailed code, and delete your account. An optional biometric lock asks for your fingerprint or face when the app opens.

## Tech stack

| Area | Library |
|---|---|
| State | `flutter_bloc` (Cubits only) |
| Navigation | `go_router` |
| Dependency injection | `get_it` |
| Errors | `dartz` `Either` with `Failure` types |
| Backend | Supabase: auth, Postgres database, storage for receipts, product documents and avatars, and edge functions in TypeScript (Deno) |
| AI | Groq, called from edge functions: `openai/gpt-oss-120b` for `ai-chat`, `qwen/qwen3.8-27b` for `extract-receipt` |
| Offline | Products cached per user in `shared_preferences`; connectivity via `internet_connection_checker_plus` |
| Auth extras | `google_sign_in` (ID token passed to Supabase), `local_auth` for the biometric lock |
| Notifications | `flutter_local_notifications` with `timezone`; `add_2_calendar` for calendar events |
| Home screen widget | `home_widget` (Android provider + iOS WidgetKit extension) |
| PDF | `pdfrx` reads the text layer of PDF invoices before scanning |
| Crash reporting | Firebase Crashlytics |
| UI | `flutter_screenutil` for sizing, Cairo font via `google_fonts`, Phosphor icons, `skeletonizer` loading states |
| Localization | `flutter_localizations` + ARB files in `lib/l10n` (English, Arabic) |

```
  main.dart              app bootstrap (env, Supabase, Firebase, DI, logo precache)
  firebase_options.dart  generated by FlutterFire
  core/
    constant/            app colors
    di/                  get_it registrations
    error/               exceptions, failures, Supabase error mapping, user-facing messages
    locale_controller/   app language (can differ from the phone's)
    logger/              AppLogger, console logger, Crashlytics reporting
    observer/            BlocObserver
    route/               go_router routes
    service/             Supabase client, storage, notifications and reminders,
                         biometrics, home widget sync, PDF reader, review prompts
    theme/               theme, palette, icons, light/dark controller
    util/                spacing, sizes, validators, formatting helpers
    widgets/             shared widgets (cards, snackbars, empty/error views,
                         connectivity banner, SakkLogo)
  features/              one folder per feature
  l10n/                  ARB files (English, Arabic) and generated localizations
assets/
  icons/                 app icon, adaptive and monochrome launcher icons, Google logo
  splash/                native splash logo
android/app/src/main/kotlin/com/sakk/app/
  WarrantyWidgetProvider.kt   Android home screen widget
ios/SakkWarrantyWidget/       iOS home screen widget (WidgetKit)

  migrations/            database schema
  functions/             edge functions: ai-chat, extract-receipt, delete-account

```

Features use clean architecture layers, but only the ones they need:

| Feature | Layers |
|---|---|
| `auth`, `chat`, `household`, `notification`, `products` | data, domain, presentation |
| `analytics`, `category` | domain, presentation |
| `details`, `forget_password`, `home`, `legal`, `onboarding`, `scan`, `splash` | presentation only |
| `nav_bar` | a single `nav_bar.dart` |

`scan` and `details` reuse the `products` data and domain layers.

## Getting started

### Requirements

- Flutter 3.41 (stable) or newer — the project needs Dart `^3.11.5`
- **Android:** Android Studio and the Android SDK. Gradle needs Java 17 or 21; Gradle 8.14 does not run on Java 25. If that is your default, use Android Studio's bundled JDK:
  ```
  export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
  ```
- **iOS:** Xcode and CocoaPods. The Podfile targets iOS 15.0.

### Environment

Create a `.env` file in the project root. It is git-ignored, but it is listed as an asset in `pubspec.yaml`, so **the app will not build without it**:

```
SUPABASE_URL=
SUPABASE_ANON_KEY=
GOOGLE_WEB_CLIENT_ID=
GOOGLE_IOS_CLIENT_ID=
```

The Firebase config (`lib/firebase_options.dart`, `android/app/google-services.json`, `ios/Runner/GoogleService-Info.plist`) is committed, so Crashlytics works without extra setup.

If you use a different `GOOGLE_IOS_CLIENT_ID`, also update the reversed client ID in `CFBundleURLSchemes` in `ios/Runner/Info.plist`.

### Run

```
flutter pub get
flutter run
```

On iOS, `flutter run` installs the pods automatically. Translations are generated from `lib/l10n/*.arb` on build; after editing an ARB file, run `flutter gen-l10n` to update them without a full build.

### Test and lint

```
flutter test
flutter analyze
```

### iOS home screen widget

The widget's Swift code is in `ios/SakkWarrantyWidget`, but its Xcode target and the `group.com.sakk.app` App Group have to be set up once in Xcode. Follow [`ios/SakkWarrantyWidget/README.md`](ios/SakkWarrantyWidget/README.md). The Android widget needs no setup.

### Regenerating icons and splash

After changing the artwork in `assets/`:

```
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

## Google sign-in

The app signs in with Google's ID token and passes it to Supabase.

- `GOOGLE_WEB_CLIENT_ID` is the **Web** OAuth client. It is used as `serverClientId` on both platforms and must be added to Supabase's Google provider.
- `GOOGLE_IOS_CLIENT_ID` is the iOS OAuth client for bundle ID `com.sakk.app`.
- **Android** needs an Android OAuth client for package `com.sakk.app` in the same Google Cloud project — one per signing key (debug, upload, and Play App Signing). Without it, choosing an account does nothing: Credential Manager reports the error as a cancellation, which the app logs as `Google sign-in cancelled`.

To print the debug and upload key SHA-1s:

```
cd android && ./gradlew signingReport
```

The Play App Signing SHA-1 is in Play Console → Setup → App integrity.

## Release builds (Android)

Release signing reads `android/key.properties` (git-ignored):

```
storePassword=
keyPassword=
keyAlias=upload
storeFile=/path/to/sakk-upload.jks
```

Without it, release builds fall back to the debug key.

## Supabase

Apply the schema from `supabase/migrations` and deploy the edge functions with the Supabase CLI:

```
supabase db push
supabase functions deploy ai-chat
supabase functions deploy extract-receipt
supabase functions deploy delete-account
```

The AI functions need a `GROQ_API_KEY` secret:

```
supabase secrets set GROQ_API_KEY=...
```
